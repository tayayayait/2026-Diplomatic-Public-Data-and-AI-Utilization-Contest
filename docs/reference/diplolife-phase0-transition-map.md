# DiploLife Phase 0 Transition Map

Last reviewed: 2026-05-29

This document fixes the Phase 0 baseline for converting the current SafeRoute AI app into the DiploLife app described in `상세서.md`.

## Decision Rules

- User-facing features that are not present in `상세서.md` must be removed or replaced.
- Internal modules may stay only when they directly support a `상세서.md` screen, state, or API behavior.
- `src/routeTree.gen.ts` is generated by TanStack Router and must not be edited by hand.
- Existing public-data, Gemini, weather, exchange-rate, embassy, and places integrations are implementation engines, not product features by themselves.
- Any feature with no verified data source must show "확실한 정보 없음" instead of inferred content.

## Unresolved Items

- S1-S9 now have a client-side Supabase Auth gate. Authenticated profile persistence and RLS-backed profile storage remain unresolved.
- S5 living-cost insight has no confirmed current data source beyond exchange rate.
- S9 notices needs a verified source mapping from the existing public-data APIs.
- Push notification channels in `상세서.md` are not currently implemented; first implementation should likely be in-app notification state unless a real push stack is selected.
- Existing Supabase schema is trip/share-oriented and must be redesigned if persistence remains required.

## Phase 0 Completion Criteria

- Target S0-S9 routes are fixed.
- SafeRoute user-facing routes are classified for replacement or deletion.
- Internal engines are classified for reuse only when tied to DiploLife screens.
- State model replacement is identified before any implementation phase.
- Documentation has a single Phase 0 reference for the transition boundary.
